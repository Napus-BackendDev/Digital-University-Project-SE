# แผน QA/QC และ UX Audit — MFU E-Questionnaires

ปรับปรุงล่าสุด: 2026-11-18 · ผู้ตรวจ: QA Reviewer (orchestrator / QA) · ผู้ลงมือแก้: Antigravity CLI (`agy`)

## 1. ระบบนี้คืออะไร

ระบบแบบสอบถามออนไลน์ของมหาวิทยาลัยแม่ฟ้าหลวง ใช้แทนการแจกแบบฟอร์มกระดาษหรือ Google Forms กระจัดกระจาย โดยผูกกับบัญชีมหาวิทยาลัย (Google Workspace `@mfu.ac.th` / `@lamduan.mfu.ac.th`) และโครงสร้างหน่วยงาน/บทบาทของมหาวิทยาลัย

| ผู้ใช้ | ทำอะไรในระบบ | หน้าหลัก |
|---|---|---|
| ผู้ตอบ (นักศึกษา บุคลากร หรือบุคคลภายนอกในฟอร์มสาธารณะ) | ดูแบบสอบถามที่ได้รับมอบหมาย ตอบ บันทึกร่าง ส่ง แก้คำตอบ (ถ้าอนุญาต) | `/forms`, `/forms/:id` |
| ผู้สร้างฟอร์ม และผู้ร่วมจัดการ (Editor / ผู้มีสิทธิ์ดูข้อมูล) | สร้างฟอร์ม ออกแบบคำถาม ตั้งกลุ่มเป้าหมาย ตั้งเวลาเปิด-ปิด เผยแพร่ แชร์ลิงก์/QR ติดตามผล ส่งออก | `/manage`, `/manage/:id`, `/analytics/:formId` |
| ผู้ดูแลระบบ (Admin) | กำหนดสิทธิ์ผู้สร้าง ตั้งค่าอีเมล/SMTP เทมเพลตอีเมล ดูฟอร์มทั้งระบบ | `/email`, เมนูสิทธิ์ |
| ระบบภายนอก (เช่น ระบบรายงานตัวบัณฑิต) | เรียก API ตรวจว่าใครตอบเสร็จแล้ว | `GET /api/v1/response/export/:formId` |

เป้าหมาย: ผู้สร้างตั้งฟอร์มให้ถึงคนที่ถูกต้องได้เร็ว ผู้ตอบตอบได้ง่ายไม่หลง และหน่วยงานติดตาม/ส่งออกผลได้รายฟอร์ม

Stack: Vue 2 + CoreUI (frontend :8080), Node/Express + Mongoose (backend :8081), MongoDB Atlas, Gmail SMTP

## 2. User Persona ที่ใช้ตรวจ

> ผู้ใช้ระบุให้ทดสอบแบบ "คนแก่มาใช้ระบบ" รายละเอียดด้านล่างเป็นสมมติฐานของผู้ตรวจ ยังไม่ได้รับการยืนยัน แก้ไขได้

**คุณสมศรี อายุ 58 ปี เจ้าหน้าที่ธุรการอาวุโส สำนักวิชาฯ**
- ใช้คอมพิวเตอร์ทุกวันแต่ใช้แค่งานที่คุ้น (อีเมล เอกสาร ระบบ ERP) ไม่ชอบลองกดสิ่งที่ไม่รู้จัก
- สายตายาว อ่านตัวหนังสือเล็กกว่า ~14px หรือสีเทาอ่อนบนพื้นขาวลำบาก ใช้จอโน้ตบุ๊ก 1366×768 ซูม 100–125%
- อ่านภาษาไทยเป็นหลัก ศัพท์อังกฤษ/ศัพท์เทคนิค (Logic Jump, Public, Draft, Toggle) ทำให้ลังเล
- ไม่เข้าใจไอคอนที่ไม่มีข้อความ กลัวกดผิดแล้วข้อมูลหาย ต้องการคำยืนยันก่อนลบ/เผยแพร่
- งานที่ต้องทำ: (1) ตอบแบบสอบถามที่ได้รับมอบหมาย (2) สร้างแบบสอบถามความพึงพอใจให้หน่วยงาน ส่งให้นักศึกษาคณะหนึ่ง และดูว่าใครตอบแล้ว ส่งออก Excel ให้หัวหน้า

เกณฑ์ UX จาก persona (ใช้ตรวจทุกหน้า):
- U1 ตัวอักษรเนื้อหา ≥ 14px ข้อความสำคัญ ≥ 15–16px คอนทราสต์ ≥ 4.5:1 (WCAG AA)
- U2 ปุ่ม/ไอคอนสำคัญมีข้อความกำกับ หรืออย่างน้อยมี tooltip + aria-label เป้ากดสูง ≥ 36–40px
- U3 คำที่แสดงเป็นภาษาไทยธรรมดา ไม่มีศัพท์เทคนิคที่ไม่อธิบาย
- U4 หน้าหนึ่งมีการกระทำหลักชัดเจนหนึ่งอย่าง ไม่มีข้อมูลซ้ำซ้อนเกินจำเป็น
- U5 การกระทำที่ย้อนกลับไม่ได้ (ลบ เผยแพร่ ส่งคำตอบ) มีคำยืนยันและบอกผลหลังทำ
- U6 ทุกสถานะว่าง/ผิดพลาดบอกว่าเกิดอะไรขึ้นและควรทำอะไรต่อ
- U7 ใช้ได้ที่ 1366×768 โดยไม่ต้องเลื่อนแนวนอน
- U8 สลับเป็นภาษาอังกฤษแล้วไม่มีข้อความไทยค้าง

## 5. รอบการทำงาน (Loop)

1. QA Reviewer แตกงานพร้อมเกณฑ์ผ่าน → ส่ง `agy` (`--mode accept-edits`, ห้ามรันคำสั่ง shell)
2. QA Reviewer ตรวจ `git diff` เทียบ baseline (`refs/napus/b1`, …) รัน Jest/build ตรวจหน้าจอจริง
3. ไม่ผ่าน → ส่งกลับ agy ในบทสนทนาเดิมพร้อมหลักฐาน · ผ่าน → อัปเดตสถานะ TC
4. ไม่ commit/push จนกว่าผู้ใช้สั่ง

## 8. ข้อ 5.1 ซ่อนเมนูจนกว่า Admin กำหนดสิทธิ์ (2026-11-19)

ผู้ใช้ยืนยันกฎ: เมนู "จัดการฟอร์ม / การวิเคราะห์ / อีเมล" ให้เห็นเฉพาะ Admin หรือผู้ที่มีบทบาทผู้สร้างฟอร์ม

กฎที่ใช้ (`canManageForms` ทั้ง `frontend/src/projects/utils/formPolicy.js` และ `backend/.../responsePolicy.js`):
- Admin → ได้
- permission matrix ของบทบาทอนุญาตหน้า manage / forms-management / create → ได้ (ตอนนี้ matrix ว่างทุกบทบาท)
- ถ้า matrix ไม่ได้กำหนด: บทบาทอาจารย์ (Lecturer) หรือเจ้าหน้าที่ (Staff) → ได้
- นักศึกษา (ค่าเริ่มต้นของผู้ลงทะเบียนใหม่), ไม่มีบทบาท, บทบาทอื่น → ไม่ได้

สิ่งที่ทำ: sidebar ใช้กฎนี้แทน `isStudent` (เดิมคนไม่มีบทบาทเห็นเมนู Admin), router guard ส่ง `/manage`, `/analytics`, `/analytics/:id`, `/email`, `/email/:id` ไป `/forms?denied=manage` พร้อมข้อความแจ้งภาษาไทย, ยังเปิด `/manage/:id` และ `/response/:id` ให้ผู้ร่วมจัดการที่ได้ลิงก์จากอีเมล, backend `POST /form` ปฏิเสธ 40300 สำหรับผู้ไม่มีสิทธิ์

QA: เทสต์ฟอร์มเก่า 1 ตัวโดน 403 เพราะผู้ใช้จำลองไม่มีบทบาท → ให้ agy ตั้งผู้ใช้จำลองเป็น Staff โดยไม่แตะ assertion; ย้าย `backend/tests/formCreate.test.js` ไป `__tests__/`
